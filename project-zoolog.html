아키텍처

메모리 2GB 서버 한 대에서 GitOps

Git에 적힌 대로 클러스터를 맞추기되돌리기 = git revert
상황서버에 접속해 명령으로 배포하면, 서버 상태가 Git과 어긋나도 알 수 없습니다
해결Actions가 이미지를 커밋 SHA 태그로 GHCR에 올리고 kustomization의 태그를 커밋하면, Argo CD가 Git과 클러스터를 비교해 맞춥니다(sync · prune · selfHeal)
결과되돌리기는 태그 커밋을 git revert 한 번 — Git과 서버가 늘 같은 상태를 가리킵니다
Argo CD core 설치 뒤 앱이 Unknown원인을 찾아 직접 생성
상황2GB 서버라 메모리를 아끼려 Argo CD를 core(API 서버 · 화면 없이)로 설치하자 앱이 Unknown에 멈췄습니다
원인상태 메시지 project default which does not exist — core 설치에는 default 프로젝트를 만드는 argocd-server가 없습니다
해결default AppProject를 직접 만들고, 설치 절차 문서에 추가했습니다
화면 서버 무중단 교체응답 실패 0회
해결화면 서버(Caddy)를 RollingUpdate(maxSurge 1 · maxUnavailable 0)로 바꾸고 readinessProbe와 preStop을 붙였습니다
결과배포 중 1초 간격 측정에서 화면 응답 실패 0회
남은 일백엔드는 2GB 메모리 한계로 Recreate(약 30초 API 중단) — 메모리 사용량을 보고 다음 단계를 정하는 중입니다
