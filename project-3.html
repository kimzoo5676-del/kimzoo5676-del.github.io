배경 & 문제

누군가와 함께 여행을 갈 때, 카카오톡으로 각자 해야 할 일과 준비물을 공유하고 맛집 링크도 올립니다. 시간이 지나면 찾기 힘들어지는데, MODI는 목표와 기간이 있는 방을 만들어, 흩어지던 할 일·일정·자료를 한곳에 모읍니다. 4인 팀에서 백엔드·인프라·AI를 맡아 App Store에 출시했고 지금도 서버를 운영하고 있습니다.

시스템 아키텍처

단일 Oracle Cloud ARM 인스턴스 위에 전 구성요소를 Docker Compose로 운영합니다. 외부에 노출된 것은 Caddy 하나뿐이고(HTTPS·TLS 자동 발급), PostgreSQL·Redis·MinIO·AI 서버는 서버 바깥으로 포트를 열지 않았습니다. 같은 Docker 네트워크 안에서 Spring Boot만 부를 수 있어서 클라우드 방화벽에서 실수로 DB 포트를 열어도 바깥에서 접근할 주소가 없습니다.

x86 러너가 만든 이미지가 ARM 서버에서 돌지 않음레지스트리 없이 배포
상황기존 서버와 GitLab · Jenkins를 더 쓸 수 없게 되어, App Store 출시 전에 서버 · 저장소 · 배포 도구를 전부 옮겨야 했습니다
원인새 서버는 Oracle Cloud Ampere A1(ARM64), GitHub Actions 러너는 x86_64라 러너에서 만든 이미지가 서버에서 뜨지 않습니다
해결QEMU 에뮬레이션으로 ARM 이미지를 만드는 대신, 러너가 소스를 rsync로 서버에 보내고 서버가 ARM에서 직접 빌드하게 했습니다
보안배포 전용 SSH 키를 따로 만들고 서버 지문은 known_hosts에 고정했습니다. 서버에는 GitHub 자격 증명을 두지 않습니다
새 서버에 rsync가 없어 배포가 멈춤배포 전 검사로

해결서버에 설치하고, 워크플로가 배포 전에 시크릿 4개와 서버의 rsync 유무를 먼저 검사해 없으면 원인을 적고 실패하게 했습니다
옮긴 데이터 대조이관 → 출시

'테스트 통과 후 배포'를 다시 세우고, 끊기지 않게

테스트와 배포를 한 워크플로로 묶기필수 체크 = gate 하나
상황Jenkins는 한 파이프라인에서 테스트 뒤에 배포가 이어졌지만, Actions에서 워크플로를 나누면 배포가 테스트 결과를 모른 채 push만 보고 돕니다
해결changes → app · server · ai → gate → deploy를 한 파일의 needs로 묶고, 바뀐 영역만 테스트하되 건너뛴 잡은 통과로 보도록 always() && !failure() && !cancelled()
판단브랜치 보호의 필수 체크는 gate 하나만 걸었습니다. 건너뛴 잡을 필수로 걸면 PR이 끝없이 기다립니다
결과첫 main 배포에서 테스트가 건너뛰어진 채 배포된 것을 실행 기록으로 찾아 비교 기준 브랜치를 고쳤습니다
서버 한 대에서 끊기지 않게 교체1,195요청 · 5xx 0건
상황서버 한 대에서 컨테이너를 내렸다 올리면 그 사이 요청이 실패합니다
해결멈춰 있던 색을 띄워 healthy가 된 뒤 활성 파일 한 줄을 바꿔 caddy reload, 옛 색은 graceful 종료. 실패하면 아무것도 전환하지 않습니다

등록 버튼을 누른 채 기다리게 하지 않기응답 1.2초
상황예전 등록은 HTTP 응답 전에 크롤링 1회와 LLM 3회를 돌아, 문서화된 최악 대기가 약 198초였고 텍스트 한 줄 등록도 실측 13초 걸렸습니다
해결PENDING으로 저장하고 바로 응답한 뒤, 크롤링 · 요약 · 태깅은 @Async 전용 스레드 풀이 처리하게 했습니다. 주소 검증만 등록 시점에 남겨 잘못된 링크는 400으로 바로 알립니다
결과실측 1.2초에 PENDING으로 응답하고, 13초 안에 DONE과 태그 5개가 채워졌습니다
서버가 남이 준 주소로 요청을 보냄 — SSRF 방어사설망 · 리다이렉트 차단
위험사용자가 올린 링크를 서버가 대신 열기 때문에, 내부망 주소를 넣으면 서버 안쪽을 들여다볼 수 있습니다
해결http/https만 받고, DNS로 풀린 IP가 루프백 · 링크로컬 · 사설 · 멀티캐스트면 거절합니다. JDK가 못 잡는 IPv6 사설 대역(fc00::/7)은 따로 검사합니다
제한리다이렉트는 따라가지 않고, 타임아웃 5초 · 응답 2MB로 묶었습니다
실패해도 영원히 「분석 중」으로 남지 않게최대 4번 · 60분 안 확정
재시도실패하면 20분 뒤 다시, 최대 4번 — 운영 DB에서 본 회복 시간 9분 · 18분을 근거로 정했습니다
캐시같은 URL을 24시간 안에 다시 올리면 앞선 결과를 재사용해 크롤링과 LLM을 부르지 않습니다
사이트Instagram · YouTube · Naver는 전용 크롤러, 나머지는 공통 크롤러가 맡습니다. 운영 서버(데이터센터 IP)에서 Instagram이 jsoup 요청에는 로그인 화면을, Java HttpClient 요청에는 JSON을 주는 것을 확인하고 Instagram 요청을 HttpClient로 바꿨습니다

AI 투두 추천 서버

방에 모은 자료를 근거로 LLM이 할 일 후보를 만드는 FastAPI 서버를 맡았습니다. 처음에는 LangGraph로 자료 선별 → 후보 생성 → 검수 → 의미 중복 제거 파이프라인을 만들었고, 실측과 운영 기록을 보며 단계를 줄여 지금은 자료 고르기 → LLM 1회 → 문자열 필터로 돕니다.

추천 응답 28초를 줄이기28.2 → 11.8초
상황운영 방(자료 35 → 46건)에서 추천이 앱 실측 평균 28.2초 걸렸습니다
원인방의 자료를 통째로 프롬프트에 넣어, 자료가 쌓일수록 호출당 토큰이 늘었습니다
해결자료를 최신순으로 고르고 프롬프트 글자 예산을 12,000자에서 3,000자로 줄였습니다
결과평균 11.8초 — 품질은 따로 재지 않았다고 결정 기록에 함께 남겼습니다
검수 단계를 넣었다가 끈 결정후보 1~3개 → 7~8개
상황'일정 짜기'처럼 바로 실행할 수 없는 후보를 거르려고 검수 단계를 넣자, 부산 방의 이런 후보가 40%에서 0~6%로 줄었지만 후보 수가 88개에서 41개로 줄고 최악 응답이 10.88초가 됐습니다
측정반려된 후보를 다시 만드는 재생성은 후보를 109 · 88개로 되살렸지만, 라운드당 LLM 호출이 2회에서 4회로 늘어 10초 넘는 응답이 30번 중 11 · 12번 나와 쓰지 않았습니다
판단심사 직전 데모 방에서 「5개 중 0개 통과」로 빈 화면이 두 번 나와 검수를 껐습니다. 자료 46건 방에서 켰을 때 후보 1~3개 · 10~13초, 껐을 때 7~8개 · 5~9초
결과코드 기본값만 0으로 바꿨을 때 compose가 1로 덮어써 효과가 없던 것을 찾아 compose 값도 고쳤습니다
쓰지 않는 단계를 걷어내기LLM 1회 호출
상황실제로 돌던 경로는 이미 LLM 1회와 중복 제거용 임베딩 1회였고, 그래프 · 검수 코드는 꺼진 채 남아 있었습니다
해결2026.10.18 LangGraph 그래프 · 검수 · 임베딩 중복 제거를 걷어내 자료 고르기 → LLM 1회 → 문자열 필터로 줄였습니다(28개 파일 −4,469줄). 아무도 읽지 않는데 자료마다 만들던 임베딩도 멈췄습니다
남은 일전환 뒤 지연은 아직 다시 재지 않았습니다

주석 한 줄에 운영 서버 부팅 실패Flyway 체크섬
상황첫 blue/green 배포가 부팅 단계에서 Migration checksum mismatch for migration version 5로 실패했습니다
원인이미 적용된 V5 · 6 · 7 · 10 마이그레이션 파일에서 주석 한 줄(티켓 번호)이 지워져 체크섬이 달라졌습니다. 서버 테스트 774개는 매번 빈 DB로 시작해 이 차이를 잡을 수 없었습니다
해결이력 테이블을 백업한 뒤 체크섬 4건을 교정해 재배포하고, 마이그레이션 파일 29개의 지문을 커밋된 목록과 비교하는 테스트를 더했습니다
결과DB 없이 도는 테스트가 과거 마이그레이션 수정 · 목록 누락 · 파일 삭제를 각각 다른 안내로 막습니다
방 자동 종료가 9시간 늦음UTC → KST
원인운영 컨테이너에 TZ가 없어 JVM이 UTC로 돌고, 날짜 경계를 판단하는 코드가 인자 없는 LocalDate.now()를 써 한국 시간 00~09시에 서버의 「오늘」이 하루 늦었습니다
해결compose에 TZ=Asia/Seoul을 넣고, 코드도 한국 시간을 명시했습니다 — 환경변수 한 줄이 빠지면 조용히 UTC로 돌아가지 않게
결과TZ를 한국보다 하루 늦은 지역으로 바꿔 돌려도 실패하는 회귀 테스트로 경계를 묶었습니다
분석 완료 알림이 1분 넘게 늦음최대 5초
원인여러 건을 연달아 공유해도 한 번만 울리게 「마지막 분석 뒤 1분 조용하면」 보내고 30초마다 확인해, 분석은 약 13초면 끝나는데 알림은 1~1.5분 뒤에 왔습니다
해결사용자 피드백으로 묶기를 없애고 확인 주기를 30초에서 5초로 줄였습니다
